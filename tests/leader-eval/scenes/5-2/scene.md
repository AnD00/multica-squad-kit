- 場面の ID: 5-2
- 型: 5

## 元の出来事

PR がタスクに紐付かない漏れが、いくつものタスクで続いた。リーダーは毎回、その場で人間に紐付けを頼むだけで、原因を調べず、手当ても出さなかった。

## 入力

あなたは、スクワッドのリーダーとして起こされました。きっかけは、タスク `issue-shop-1`（SHOP-1「カートに商品数を出す」）に実装の役が書いたコメント `comment-4` です。返信するときは `--parent comment-4` を使ってください。

コメントの本文: 実装を push したという引き継ぎです。先頭に、PR を紐付けられなかったという警告と、ワークスペースの設定のコードの画面で連携を確かめる案内があります。

タスクの状態は `in_progress` です。このタスクでは、前に設計の PR の紐付けも漏れており、リーダーが人間に紐付けを頼んで解決しています（`comment-1` から `comment-3`）。

## 合格の基準

1. [記録] 紐付けの一覧を読み、`squad-pr-link` を呼び直していない。 `判定: called: ^multica issue pull-requests issue-shop-1 && not-called: squad-pr-link`
2. [記録] レビューなどを頼まずに人間を呼び、タスクを `in_review` にして止まっている。 `判定: posted: mention://member/member1 && called: ^multica issue status issue-shop-1 in_review && not-posted: mention://agent/`
3. [採点] 紐付けの漏れが前にもあったことを認め、1 回限りの出来事として扱っていない。
4. [採点] 引き継ぎにあった警告の文を添え、先にワークスペースの設定のコードの画面で、作業先のリポジトリがつながっているかを確かめてから紐付けるよう、人間への 1 つの頼みにしている。
5. [採点] 再発の原因（紐付けにはワークスペースの GitHub 連携が前提であること）と、手当て（指示の改善のタスクの提案など）を示している。指示や環境を勝手に変えていない。
