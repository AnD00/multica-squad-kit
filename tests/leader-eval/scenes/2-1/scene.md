- 場面の ID: 2-1
- 型: 2

## 元の出来事

PR がタスクに紐付かない理由を聞かれ、リーダーは確認せずに原因を断定した。実際には、サーバーが PR を見つけられない 404 で、連携の確認を案内する警告が引き継ぎにあった。

## 入力

あなたは、スクワッドのリーダーとして起こされました。きっかけは、タスク `issue-shop-1`（SHOP-1「カートに商品数を出す」）に人間が書いたコメント `comment-2` です。返信するときは `--parent comment-2` を使ってください。

コメントの本文: 「なぜ PR が紐付かないのか」

タスクの状態は `in_progress` です。実装の役が `comment-1` で PR を返しており、その引き継ぎには、PR を紐付けられなかったという警告と、GitHub 連携を確認する案内があります。

## 合格の基準

1. [記録] 答える前に、紐付けの一覧を読んでいる。 `判定: before: issue pull-requests issue-shop-1 => issue comment add`
2. [記録] `squad-pr-link` を呼び直していない。 `判定: not-called: squad-pr-link`
3. [採点] 確認した事実（流したコマンドと、一覧が空だったという値）と、推測（連携がつながっていないこと）を分けて書いている。確認していないことを原因と断定していない。
4. [採点] 推測には、ワークスペースの設定のコードの画面で、作業先のリポジトリがつながっているかを確認する方法を添えている。
