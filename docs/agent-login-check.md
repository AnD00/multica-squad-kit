# エージェント用の Claude のログインの確認

ホストの準備（`prepare_host`）は、エージェント用の Claude にログインしているかを `claude auth status` で確認する。この文書は、その呼び方と、結果ごとの止まり方の設計と、その理由を書く。使う人への案内は `manual.md` に書く（[利用者向けの文書の変更](#利用者向けの文書の変更)）。

## 目的と範囲

ログイン済みの人が、入口（`install.sh`）を標準入力から流すと、ホストの準備でログインを求められて止まっていた。流し直しても毎回同じところで止まるので、導入も更新も進めない。ログイン済みならログインの確認を通過し、ログインしていないときだけログインを案内するようにする。

原因は、次の二つが重なったことである。

1. 入口を標準入力から流すと、セットアップは標準入力を端末（`/dev/tty`）にして動く（[標準入力から流すとき](install.md#標準入力から流すとき)）。ログインの確認の `claude auth status` もこの標準入力を受け継ぐ。macOS では、標準入力が `/dev/tty` のとき、Claude の CLI（Bun）が `EINVAL: invalid argument, kqueue` を出して終了コード 1 で落ちる
2. ログインの確認は、`claude auth status` の終了コードが 0 以外なら、理由を見ずにログインを案内して止まる。そのため、CLI の異常終了がログイン切れとして案内される

1 は、macOS、Claude Code 2.1.322、Bun v1.4.4 で再現した。疑似端末の中で `claude auth status </dev/tty` は同じエラーで終了コード 1 になる。標準入力を `/dev/null` にすると、同じ疑似端末の中でも JSON を返す。

次は対象にしない。

- Claude の CLI（Bun）の kqueue の不具合そのものの修正。原本の外の製品のため。原本は呼び方で避ける
- Codex のログインの確認（`codex login status`）。今回の不具合が見られておらず、Rust 製で同じ原因に当たらないため。呼び方も止まり方も今のままにする
- 入口が質問を端末から読む方式。質問に答えるのに要り、今回の原因はログインの確認の呼び方で避けられるため。`install.sh` と、`setup.sh` が質問を読む方法は変えない
- セットアップのほかの外部の CLI の呼び方。今回の不具合が見られていないため

## 呼び方

`claude auth status` の標準入力を `/dev/null` にして呼ぶ。標準出力と標準エラーは、どちらも画面に流さずに受け取り、[結果の分け方](#結果の分け方)で読む。終了コードも受け取る。

確認のコマンドは何も読まないので、標準入力を `/dev/null` にしても動きは変わらない。こうすると、セットアップの標準入力が端末・パイプ・ファイルのどれでも、CLI が受け取る標準入力は同じになる。入口の流し方によらず、同じ呼び方で確認できる（[入口の流し方と動作](#入口の流し方と動作)）。

標準エラーを受け取るのは、確認に失敗したときに、既知の不具合かを見分けるためである（[確認に失敗したときの表示](#確認に失敗したときの表示)）。受け取った出力は、標準出力も標準エラーも画面に出さない。アカウント情報や認証の値を含みうるためである。今は標準エラーをそのまま画面に流しているが、作成の進みの一覧（[作成の進み](screens.md#作成の進み)）の途中に出ると表示も崩れる。受け取りに一時ファイルを使うときは、確認のあとすぐ消す。

検討した案と選ばなかった理由は次のとおり。

| 案 | 選ばなかった理由 |
| --- | --- |
| 入口が、セットアップの標準入力を `/dev/tty` にしない | セットアップが質問を端末から読めなくなる。質問の読み方を変えると、`setup.sh` の質問のすべてに及ぶ |
| セットアップの最初で、子のプロセスの標準入力をまとめて `/dev/null` にする | 質問を読む処理と分ける必要があり、変更が広い。ほかの CLI では不具合が見られていない |
| 疑似端末（`script` など）の中で CLI を呼ぶ | 道具と OS ごとの違いが増える。端末を渡す理由がない |

## 結果の分け方

標準出力の最初の JSON の値と、終了コードで分ける。ログインしていないかは、CLI が `loggedIn: false` と答えたかだけで決め、終了コードでは決めない。

| 標準出力の最初の値 | 終了コード | 動作 |
| --- | --- | --- |
| オブジェクトで、`loggedIn` が `true` | 0 | 通過する。今までどおり、何も出さずに次へ進む |
| オブジェクトで、`loggedIn` が `false` | 問わない | 今までと同じ「エージェント用の Claude にログインしてください」の案内で止まる |
| オブジェクトで、`loggedIn` が `true` | 0 以外 | 確認に失敗したとして止まる |
| 上のどれでもない（空、JSON でない、オブジェクトでない、`loggedIn` が真偽値でない） | 問わない | 確認に失敗したとして止まる |

`loggedIn: false` を終了コードで分けないのは、同じ CLI でも、ログインしていないときの終了コードが呼び方で変わるためである。Claude Code 2.1.322 では、端末のないところで呼ぶと終了コード 0、疑似端末の中で呼ぶと終了コード 1 で、どちらも `loggedIn: false` を返した。

`loggedIn: true` でも終了コードが 0 以外なら通過させない。CLI が失敗したと言っているので、出力が途中までのおそれがあり、確認したことにならないため。人間は、[確認に失敗したときの表示](#確認に失敗したときの表示)の診断と、端末から流す確認で判断できる。

最初の JSON の値だけを読むのは、端末のないところで呼ぶと、CLI が JSON のあとに端末の制御文字（`ESC [ ? 1 l` など）を出すためである。今の確認は出力の全体を JSON として読むので、制御文字があると読めずにログインを案内する。最初の値のあとに続くものは読まず、捨てる。最初の値の前に何かあるときは、読めない出力として扱う。

## 確認に失敗したときの表示

確認に失敗したときは、ログインを案内しない。確認そのものに失敗したことと、診断を示して、終了コード 1 で止まる。止まる前に、デーモンの操作など、ログインの確認のあとの処理は行わない。今のログインの案内と同じである。

CLI の出力は、標準出力も標準エラーも、表示しない。一部も転載しない。`claude auth status` の出力には、メールアドレスや組織の名前などのアカウント情報が入り、標準エラーには認証の値が出るおそれもあるためである（[表示する項目を絞る理由](#表示する項目を絞る理由)）。

表示は、今の止まり方（作成の進みの一覧の手順を `✖` にし、`エラー:` の行を出す）に、診断を続ける。診断は、`エラー:` の行のあと、標準エラーに出す。

```text
  ✖ ホストを準備
エラー: エージェント用の Claude のログインを確認できませんでした。ログインが切れているとは限りません。端末から CLAUDE_CONFIG_DIR=/Users/me/.multica-agent/claude claude auth status を流して、ログインの状態を確認してから流し直してください。問い合わせるときは、下の診断の行だけを添えてください。
  診断（claude auth status）:
    分類: Claude の CLI の既知の不具合（kqueue）
    終了コード: 1
    標準出力の最初の値: 空
    標準出力: なし
    標準エラー: あり（内容は省略）
```

- `エラー:` の行には、ログイン切れとは限らないこと、単独で確認するコマンド、問い合わせには診断の行だけを添えることを書く。コマンドの `CLAUDE_CONFIG_DIR` は、今の案内と同じく実際のパスにする。パスには利用者の名前が入りうるので、診断には入れない
- 診断は、見出しの下に、4 つの空白で字下げして、下の表の 5 行をこの順に出す
- 作成の進みの一覧を書き換えないとき（`✔ 手順  値` の行を順に出す画面）も、`エラー:` の行と診断は同じに出す

### 診断の項目

診断の値は、数値と、この表に書いた固定の文だけで組み立てる。CLI の出力から取った文字列（JSON のキーや値、JSON の前後の文、標準エラーの行）は、一字も入れない。

| 項目 | 値 |
| --- | --- |
| 分類 | 下の分類の表のどれか |
| 終了コード | `claude auth status` の終了コードの数 |
| 標準出力の最初の値 | `空`、`JSON として読めない`、`オブジェクトでない`、`loggedIn が真偽値でない`、`loggedIn が true` のどれか。[結果の分け方](#結果の分け方)の読み方のとおりに決める |
| 標準出力 | `あり（内容は省略）` か `なし` |
| 標準エラー | `あり（内容は省略）` か `なし` |

`loggedIn が false` は、ログインの案内で止まるので、診断には出ない。空白だけの出力は `空` にする。最初の値の前に何かある出力（JSON の前に警告がある場合など）は、`JSON として読めない` にする。

分類は、上から順に見て、最初に当てはまるものにする。

| 分類 | 当てはまるとき |
| --- | --- |
| `Claude の CLI の既知の不具合（kqueue）` | 標準エラーに、`EINVAL` と `kqueue` の両方の文字の並びがある |
| `CLI がログイン済みと答えたまま失敗した` | 標準出力の最初の値が `loggedIn が true` で、終了コードが 0 以外 |
| `CLI の出力を読めない（詳細は省略）` | 上のどれでもない |

- kqueue の分類は、今回の原因を画面で見分けるために置く。当てはまっても、もとの行、例外の文、スタックは出さない
- 当てはまらない出力は、`詳細は省略` の分類にする。出力を見せる例外は作らない。ほかの既知の不具合を見分けたくなったら、同じ形で固定の分類を足す
- 標準出力と標準エラーは、バイト列として読む。UTF-8 として読めない出力や制御文字があっても、表示は変わらない
- 出力を読む処理が失敗したときは、その処理のエラー（入力を含みうる）を画面に出さず、`Claude のログインの確認の出力を読めませんでした。` の固定の文で止まる

### 問い合わせに添えるもの

配布者へ問い合わせるときに添えるのは、診断の 6 行（見出しと 5 項目）だけにする。`エラー:` の行を含む画面の全体は添えない。`エラー:` の行の確認のコマンドには、利用者の名前が入りうるパスがあるためである。

端末から流す `claude auth status` は、本人がログインの状態を確認するために残す。その出力は、アカウント情報が出るので添えない。`manual.md` の案内も、この範囲に合わせる（[利用者向けの文書の変更](#利用者向けの文書の変更)）。

### 表示する項目を絞る理由

出力から漏れてはいけないものを選んで伏せるのではなく、出してよいものだけを固定の形で出す。伏せる方式では、CLI が新しい項目や自由な文を出すと漏れるためである。

| 案 | 診断と安全性 | 判断 |
| --- | --- | --- |
| 固定の項目と、既知のエラーの分類だけを出す | 今回の kqueue の手がかりを残し、出力の文字列を外へ出さない | 選ぶ |
| 終了コードと、固定の失敗の案内だけを出す | 最も小さいが、今回の原因を画面だけでは見分けにくい | 選ばない |
| メールアドレスやトークンを正規表現で伏せ、残りを出す | 未知の項目、形式、自由な文から漏れる | 選ばない |
| 出力をそのまま出す（前の設計） | アカウント情報や認証の値が、ログと問い合わせに入る | 選ばない |

文は、`manual.md` の止まったときの表と合わせる（[利用者向けの文書の変更](#利用者向けの文書の変更)）。

## 入口の流し方と動作

入口をファイルに取って流す場合と、`bash setup.sh` で流す場合の動作は変えない。直すのはログインの確認の呼び方だけで、`install.sh` と、`setup.sh` が質問を読む方法は変えないためである。

| 流し方 | セットアップの標準入力 | ログインの確認の CLI の標準入力 |
| --- | --- | --- |
| 入口を標準入力から流す（`curl ... \| bash -s --`） | `/dev/tty`（今のまま） | `/dev/null`（今は `/dev/tty`） |
| 入口をファイルに取って流す（`bash install.sh`） | 入口の標準入力（今のまま） | `/dev/null`（今は入口の標準入力） |
| `bash setup.sh` | 流した人の標準入力（今のまま） | `/dev/null`（今は流した人の標準入力） |

ファイルと `bash setup.sh` の場合も、CLI の標準入力は `/dev/null` に変わる。確認のコマンドは標準入力を読まないので、結果は変わらない。ログイン済みなら通過し、ログインしていなければ今と同じ案内で止まる。

変わらないことは、次で確認する。

1. `install.sh` と `setup.sh` の差分がないこと。PR の差分で確認する
2. 入口のテスト（`tests/install-test.sh`）を変えずに通すこと。ファイルとして流す場合は、セットアップが入口の標準入力を受け継いで答えを読むことを確認している。標準入力から流す場合は、端末から答えを読むことを確認している
3. ホストの準備のテスト（`tests/host-test.sh`）で、セットアップの標準入力を端末・パイプ・ファイルにした 3 通りで、同じ結果になること（[テスト](#テスト)）
4. 人間が macOS の実機で、ログイン済みの環境から、入口を標準入力から流す場合と `bash setup.sh` で流す場合の両方を流し、ホストの準備を通過すること

## テスト

`tests/host-test.sh` の `claude` のスタブを広げ、ログインの確認の呼び方と分け方を確認する。スタブで行うので、本物の CLI もネットワークも要らず、macOS と Ubuntu の CI で通る。

スタブは、受け取った標準入力が端末なら（`[[ -t 0 ]]`）、kqueue のエラーと同じ文を標準エラーに出して終了コード 1 で終わる。macOS の CLI の不具合の代わりである。本物は `/dev/tty` のときだけ落ちるが、スタブは端末ならいつも落ちるので、本物より厳しく確認する。

| 確認すること | スタブの動作 | 期待すること |
| --- | --- | --- |
| 標準入力が端末でも落ちない | セットアップの標準入力を `/dev/tty` にして流す。疑似端末は `tests/stdin-tty-run.py` の `tty` で作る | 通過し、次の処理（デーモンの確認）へ進む |
| 流し方によらず同じ | セットアップの標準入力を端末・パイプ・ファイルにする | 3 通りとも通過する。スタブが受け取った標準入力が端末でない |
| ログインしていない | `{"loggedIn":false}` を、終了コード 0 と 1 で返す | どちらも今と同じログインの案内で止まり、デーモンを操作しない |
| CLI が kqueue で落ちる | 標準出力は空、標準エラーに kqueue のエラーとスタックを出し、終了コード 1 | ログインを案内しない。分類が kqueue の診断を出して止まる。エラーの文（`invalid argument`）とスタックの行は出ない |
| 読めない出力で終了コード 0 | 空、JSON でない文、警告のあとの JSON、`loggedIn` のないオブジェクト、`loggedIn` が文字列 | 標準出力の最初の値がそれぞれの固定の文になり、分類が `詳細は省略` の診断で止まる。ログインを案内しない |
| ログイン済みでも終了コードが 0 以外 | `{"loggedIn":true}` に、ダミーのメールアドレスと組織の名前を足し、終了コード 1 | 分類が `ログイン済みと答えたまま失敗した` の診断で止まる |
| 出力を表示しない | 標準出力と標準エラーに、ダミーのメールアドレス、組織の名前、認証の値、未知のキーと値、JSON の前後の文、UTF-8 でないバイト、制御文字を入れる | そのどれも、セットアップの標準出力にも標準エラーにも出ない。診断の 5 項目は出る |
| JSON のあとの制御文字 | `{"loggedIn":true}` のあとに `ESC [ ? 1 l` などを出し、終了コード 0 | 通過する |

確認に失敗した場合は、診断の行が表の値の組み合わせだけであることを、行ごとに比べて確認する。ダミーの値を探すだけでは、未知の値の漏れを見逃すため。ログインの案内で止まる場合と、確認に失敗した場合は、互いの文が出ていないことも確認する。取り違えを戻さないため。今のテストの、Claude だけ・Codex だけを使う場合の確認（使わない側のログインを求めない）は、そのまま通す。

## 利用者向けの文書の変更

`manual.md` の「止まったときに見ること」の表に、確認に失敗したときの行を足す。添えるものは[問い合わせに添えるもの](#問い合わせに添えるもの)のとおりにする。ログイン切れの案内とは別の行にし、取り違えないようにする。

| 表示・状態 | 確認と再開 |
| --- | --- |
| 「エージェント用の Claude のログインを確認できませんでした」と出て止まった | ログインが切れているとは限らない。端末から表示されたコマンドを流して、ログインの状態を確認する。その出力にはアカウント情報が出るので、人に渡さない。診断の分類が kqueue のときは、Claude Code を更新して流し直す。直らなければ、表示された診断の行だけを添えて配布者へ返す。画面の全体は添えない |

`docs/install.md` の[標準入力から流すとき](install.md#標準入力から流すとき)には、セットアップの子のプロセスも `/dev/tty` を受け継ぐことと、ログインの確認ではそれを避けることを書き、この文書へつないだ。
