# エージェントの実行で関所と見張りを PATH から選ぶ

エージェントの実行のシェルで、`gh` が関所に解決し、見張りのスクリプトを名前で呼べるようにする。デーモンの起動のしかたや、ランタイムが PATH を組み替えるかどうかによらず、そうなるようにする。あわせて、関所か見張りが使えない実行は、始めの確認で止まり、人間を呼ぶ。

この文書は、その仕組みと理由を書く。使う人への手順は `manual.md` に、テストの範囲とバージョンを出す前の確かめは `CONTRIBUTING.md` に書く（[利用者向けの文書の変更](#利用者向けの文書の変更)）。

## 目的と範囲

今は、関所のディレクトリ（`~/.multica-agent/bin`）を PATH の先頭に置くのは、セットアップが起動したデーモンの環境と、プロジェクトのシェル起動ファイルの 2 つである。どちらも、次のときに崩れる。崩れると、エージェントの `gh` は本物の `gh` になって関所を通らず、見張りは名前で見つからない。

- デーモンをセットアップの外で起動した。`multica daemon start` を手で流した、ログインの PATH のまま起動し直したなど
- ランタイムが、起動ファイルのあとで PATH を上書きした。Claude Code のシェルのスナップショットがこれに当たる

この変更では、PATH の直し方を Claude と Codex のそれぞれで決め、関所と見張りを使う実行の始めに確認を置く。どちらもセットアップの流し直しで反映する。次は対象にしない。

- 見張りや `gh` を絶対パスで呼ぶように、指示を変えること。名前で呼ぶ今の指示と、関所を迂回しない決まりを保つ
- デーモンを誰が起動し直したかを突き止めること
- `git push` の関所（`pre-push`）を変えること。Git の設定の環境変数で効くので、PATH に頼らない
- セットアップの外で起動したデーモンで、Codex のログインと設定がエージェント用に分かれないこと。これはデーモンの `CODEX_HOME` に頼り、今のとおりセットアップの確かめ（`daemon_has_agent_env`）で直す

## 崩れる仕組み

Claude Code は、Bash の道具のコマンドごとに `zsh -c` を起動する。zsh は `$ZDOTDIR/.zshenv` を読んで関所を先頭に置くが、そのあとで Claude Code がシェルのスナップショットを読み込む。スナップショットは、セッションの始めに読み取った PATH を `export PATH=...` で書き戻すので、関所を外した PATH に戻る。デーモンの PATH に関所がなければ、スナップショットにも入らない。

Codex は、シェルのスナップショットの機能（`shell_snapshot`）を既定で使う。スナップショットは、利用者のログインシェルを対話で起動して読み取り、コマンドの前に PATH ごと書き戻す。Codex が使うシェルは `$SHELL` ではなく、OS の利用者の情報のシェルである。Ubuntu では bash になり、ログインの bash は `BASH_ENV` も `ZDOTDIR` も読まないので、関所が入らない。macOS の zsh でも、`/etc/zprofile` の `path_helper` が PATH を並べ替える。

Codex のログインシェルを止める `allow_login_shell = false` は、エージェント用の `CODEX_HOME` の設定にある。Multica はタスクごとの `CODEX_HOME` を、デーモンの `CODEX_HOME` から作り、なければ利用者の `~/.codex` から作る。セットアップの外で起動したデーモンでは、この設定が効かない。

Multica は、エージェントの環境変数（custom_env）のうち、`PATH`、`HOME`、`SHELL`、`CODEX_HOME` などを受け付けない。そのため、custom_env で PATH を直接渡す方法は使えない。

## PATH の直し方

Claude と Codex のどちらも、エージェントごとの設定で直す。エージェントの設定はセットアップが Multica に書き、デーモンの起動のしかたに左右されない。

| ランタイム | 直し方 | 効く理由 |
| --- | --- | --- |
| Claude | custom_env に `CLAUDE_ENV_FILE` を足し、プロジェクトのシェル起動ファイル `env.sh` を指す | Claude Code は、コマンドごとに、スナップショットのあとでこのファイルを読む |
| Codex | エージェントの custom_args に `-c allow_login_shell=false` と `-c features.shell_snapshot=false` を足す | ログインシェルとスナップショットを使わなくなり、起動ファイルの `.zshenv` か `BASH_ENV` が最後に PATH を決める |

### Claude

Claude のモデルの役の custom_env に、`CLAUDE_ENV_FILE=<プロジェクトのシェルのディレクトリ>/env.sh` を足す。今の `CLAUDE_CODE_SHELL` と同じく、Claude のモデルの役にだけ付ける。

Claude Code は、Bash の道具のコマンドを、スナップショットの読み込み、`CLAUDE_ENV_FILE` の内容、コマンドの順に組み立てる。`env.sh` は関所のディレクトリが先頭になければ先頭に置くので、スナップショットが PATH を書き戻したあとでも、関所が先頭になる。`env.sh` は POSIX のシェルの書き方だけを使うので、zsh でも bash でも読める。

専用のファイルは作らず、`env.sh` を使う。中身が同じで、セットアップの確かめ（`host_check_guards`）が、すでに `env.sh` の動きを確かめているため。印のない既存の `env.sh` を残すときの扱いも、今と同じにする。

Claude Code は、`CLAUDE_ENV_FILE` の内容をセッションごとに覚える。`env.sh` の中身は実行の途中で変わらないので、困らない。サンドボックスで認証情報の環境変数を消す設定のときは読まないが、今のエージェントはこの設定を使わない。

### Codex

Codex のモデルの役の custom_args に、次の 2 組を足す。Multica は custom_args を `codex app-server` にそのまま渡し、`-c` の上書きはタスクごとの `config.toml` より優先する。

- `-c allow_login_shell=false`。Codex が `config.toml` を利用者の `~/.codex` から作ったときも、ログインシェルを使わない
- `-c features.shell_snapshot=false`。スナップショットを読み取らず、書き戻さない

この 2 つで、Codex のコマンドは非ログインの `zsh -c` か `bash -c` で動く。zsh は custom_env の `ZDOTDIR` の `.zshenv` を、bash は `BASH_ENV` の `env.sh` を読み、関所を先頭に置く。OS の利用者のシェルが zsh でも bash でも、同じになる。

スナップショットを止めると、利用者の別名と関数はエージェントのコマンドに入らない。エージェントには不要で、関所を迂回する別名も入らなくなる。

`common/codex/config.toml` の `allow_login_shell = false` と、それを確かめるセットアップの処理は残す。セットアップが起動したデーモンでは、両方が同じ値になる。

### custom_args の合わせ方

今のセットアップは custom_args を書かないので、custom_env と同じ考えで、セットアップが持つ値だけを合わせる。

- 今の custom_args を読み、`allow_login_shell` と `features.shell_snapshot` を上書きする `-c` と `--config` の組を除く。`-c key=value` の 2 語と、`--config=key=value` の 1 語の形を、どちらも除く
- スナップショットを有効にする `--enable shell_snapshot` と `--enable=shell_snapshot` も除く。ほかの機能の有効化は残す
- Codex のモデルの役には、除いたあとに 2 組を足す。Claude のモデルの役には足さない
- ほかの引数は、順も含めて残す。結果が今と同じなら書かない
- エージェントを作るときも、同じ値を渡す

使うランタイムを変えて、役が Claude から Codex に移るときは足し、Codex から Claude に移るときは除く。custom_env の `CLAUDE_ENV_FILE` も、今の Claude の変数と同じく、合わせる前に除いてから足し直す。

## 実行の始めの確認

関所か見張りを使う実行は、ほかの処理より先に `squad-preflight` を流す。確認が通らなければ、GitHub への書き込みも見張りの呼び出しもせずに止まり、人間を呼ぶ。PATH の直し方が効かない構成や、見張りの欠けを、書き込みの前に見つけるため。

### 確かめるもの

`squad-preflight` は、ほかの見張りと同じく `common/monitor/` に置き、セットアップが関所のディレクトリに置く。引数を取らず、自分が置かれたディレクトリを関所のディレクトリとして、次を確かめる。

1. `command -v gh` が、関所のディレクトリの `gh` である
2. セットアップが置く見張り（`squad-` で始まる、`squad-preflight` を除くもの）のそれぞれで、`command -v` が関所のディレクトリのそのファイルを返す

確かめる見張りの一覧は、`squad-preflight` の中に書く。テストで `common/monitor/` のファイルと照らし合わせ、見張りを足したときの書き忘れを防ぐ。

確認の入口には POSIX sh を使う。Bash の起動時に `BASH_ENV` が PATH を直す影響を受けず、呼び出し元から渡された PATH をそのまま判定するため。

すべて通れば、1 行の結果を出して 0 で終わる。どれかが通らなければ、通らなかったものごとに、使えないもの、実際に解決したパス（なければ「見つからない」）、直し方を出して、1 で終わる。

`squad-preflight` は名前で呼ぶ。関所のディレクトリが PATH にないときは、シェルが「コマンドが見つからない」で 127 を返す。これも通らなかったと扱う。絶対パスで呼ばないのは、関所を迂回しない決まりと揃え、PATH の崩れそのものを確認で見つけるため。

### 直し方の案内

| 通らなかったもの | 案内する直し方 |
| --- | --- |
| `squad-preflight` が見つからない | 関所のディレクトリが PATH にない。動いているタスクがないときに、同じプロジェクトでセットアップを流し直す |
| `gh` が関所でない | 実行のシェルが、関所より先に別の `gh` を選んでいる。同じくセットアップを流し直す。直らなければ、エージェントの custom_env の `CLAUDE_ENV_FILE`（Claude）か custom_args（Codex）を確かめる |
| 見張りが見つからない、関所のディレクトリのものでない | 見張りが欠けたか、別の同じ名前のものが先にある。同じくセットアップを流し直して、見張りを置き直す |

案内は `squad-preflight` の出力に書き、見つからないときの案内は共通スキルに書く。人間を呼ぶ報告には、出力をそのまま添える。

### 置き場所と対象の役

確認の手順は、共通スキル squad-handoff に節を足して書く。GitHub に書き込む、または `squad-` の見張りを呼ぶ実行は、その最初にこの節に従う。要件を決める役のように、どちらもしない実行では流さない。

役の指示では、見張りを呼ぶ役に、確認を先に流すことを書く。

| 役 | 指示に書くこと |
| --- | --- |
| 進行 | 「受け取ったら確かめること」の先頭で、squad-handoff の確認の節に従う。返事を待つ処理の分かれ道より先に流す |
| CI の見張り、Dependabot のマージ、使用上限の見張り | 共通スキルを持たないので、見張りを呼ぶ前に `squad-preflight` を流し、通らなければ止まって呼ぶ人間に知らせることを、指示に直接書く |

ほかの役（設計、実装、修正、レビュー、QA）は、共通スキルの節で確認する。共通スキルの更新を飛ばしたプロジェクトでは、更新するまで、これらの役は確認を流さない。PATH の直し方そのものは、役の指示と同じくセットアップで反映する。

### 止まるときの扱い

確認が通らなかった実行は、次のとおりにする。

1. 確認のあとの処理は、GitHub の読み取りも含めて流さない。見張りも呼ばない
2. squad-handoff の「人間を呼んで止まるとき」に従い、呼ぶ人間をメンションしてタスクを `in_review` にする
3. コメントに、使えなかったものと直し方を書く。`squad-preflight` の出力があれば、そのまま添える

Multica へのコメントと状態の変更は、`multica` の CLI で行い、関所を通らないので、確認が通らなくても行える。

タスクのない見張り（オートパイロットの実行）は、オートパイロットの指示の報告のしかたで、呼ぶ人間に知らせる。

## セットアップの流し直しで反映する

同じプロジェクトでセットアップを流し直すと、次が反映される。既存の導入先に、手で足すものはない。

- `squad-preflight` を、ほかの見張りと同じく関所のディレクトリに置く
- 各役の custom_env と custom_args を、上のとおり合わせる
- 役の指示と、共通スキルを今のとおり更新する

custom_env と custom_args は、エージェントの次の実行から効く。デーモンを起動し直す必要はない。

## テストと実機の確かめ

受け入れ条件のうち、仕組みの判定はスタブを使う自動テストで、実際のランタイムの動きは人が実機で確かめる。

| テスト | 確かめること |
| --- | --- |
| `tests/squad-preflight-test.sh`（新規） | すべて使えるとき 0 で終わること。`gh` が関所より後ろのとき、見張りが 1 つ欠けたときに、使えないものと直し方を出して 1 で終わること。確かめる見張りの一覧と `common/monitor/` の照らし合わせ |
| `tests/shell-test.sh` | Claude Code のコマンドの組み立てをまねて、関所のない PATH を書き戻すスナップショットのあとに `env.sh` を読むと、`gh` が関所に、見張りが名前で解決すること。zsh と bash の両方 |
| `tests/project-test.sh` | Claude のモデルの役にだけ `CLAUDE_ENV_FILE` が付くこと。Codex のモデルの役にだけ custom_args の 2 組が付き、ほかの引数を残すこと。既存の上書きを除いて重ねないこと。ランタイムを変えたときに付け外しすること。流し直しで変わらなければ書かないこと |
| `tests/agent-templates-test.sh` | 進行の役と 3 つの見張りの指示、共通スキルに、確認の手順があること |

実機では、認証済みのデーモンとランタイムで、次を確かめる。スタブでは、Claude Code と Codex の実際のコマンドの組み立てを確かめきれないため。

1. 関所のない PATH で、`multica daemon start` をセットアップの外で流す。Claude と Codex の役の実行で、`command -v gh` が関所に、`squad-dispatch-pick`・`squad-pr-watch`・`squad-review-wait` が名前で解決する
2. セットアップが起動したデーモンで、1 と同じ結果になる
3. 見張りを 1 つ外したホストで、進行の役の実行が、書き込みと見張りの呼び出しをせずに止まり、人間を呼んで、使えないものと直し方を書く
4. 既存の導入先で、同じプロジェクトのセットアップを流し直したあと、1 から 3 が成り立つ

この変更の PR では、マージの前に人が 1 から 4 を確かめ、結果を PR に書く。以後は、バージョンを出す前の VM の確かめに 1 を足す。

## 利用者向けの文書の変更

`manual.md` と `CONTRIBUTING.md` に、使う人と原本を変える人への手順を書く。この文書の設計の理由は写さない。

`manual.md` は、次を変える。

- 「既存の関所の確認」の、シェル起動ファイルの段落。Claude はコマンドごとに `env.sh` を読み、Codex はログインシェルとスナップショットを使わないことを足し、この文書へリンクする
- 「止まったときに見ること」の表に、エージェントの実行が始めの確認で止まった行を足す。直し方は、[直し方の案内](#直し方の案内)の表と同じにする

`CONTRIBUTING.md` は、次を変える。

- 「テストで確かめる範囲」に、実行の始めの確認と、ランタイムのコマンドの組み立てのまねを足す
- 「バージョンを出す前に VM で確かめる」の項目 2 に、中のエージェントの実行で `gh` が関所に、見張りが名前で解決することを足す

## 検討した案

| 案 | 選ばなかった理由 |
| --- | --- |
| 指示で、見張りと `gh` を絶対パスで呼ぶ | 依頼の対象外。`gh` を名前で呼ぶ道具や見張りの中の `gh` は、関所を通らないまま残る |
| custom_env で `PATH` か `CODEX_HOME` を渡す | Multica が受け付けない |
| ZDOTDIR に `.zprofile` と `.zlogin` を置き、ログインの zsh でも関所を先頭に戻す | ログインの bash（Ubuntu の Codex）に効かない。Claude のスナップショットにも効かない |
| Claude Code のスナップショットを止める | 止める設定が公開されていない。`CLAUDE_ENV_FILE` で足りる |
| 実行の始めの確認を、指示の中のシェルの 1 行にする | 確かめる見張りの一覧と直し方が役の指示ごとに散り、テストで照らし合わせにくい |
| 確認を、セットアップのデーモンの確かめだけで済ませる | セットアップの外でデーモンを起動し直したあとは流れない |
| デーモンをセットアップの外で起動できないようにする | Multica の CLI の起動を止められない。起動のしかたによらずに直すほうが確か |
