# リーダーの手順: 実装・修正の振り分け

このファイルはリーダーの手順で、リーダーだけが読む。リーダーの指示の「場面と手順」から、実装や修正を頼むときに読む。前の実行で読んだ記憶で済ませず、その実行の中で読む。

役の有無と系統で分かれる手順は、場合分けで書く。どの場合かは、リーダーの指示の「このスクワッドの役」で決まる。有効な実装・修正の役の一覧も、そこにある。

## 回し先と使用率

新しくコードを書く仕事とバグは実装の役へ、レビューの指摘・コンフリクト・CI の失敗は修正の役へ回す。依頼ごとに使用率を読み直し、30 分より古い値は使わない。

実装のフェーズを頼む前と、修正を頼む前に、`leader-principal.md` の「判断する時機」で印を確認する。最上位の役がないときは、この確認を飛ばす。修正を頼む前は、先に `leader-flow.md` の「修正の依頼の前に確認する順」に従い、人間を呼ぶ確認と印の確認の順を守る。

## 系統ごとの選び方

### 両系統があるとき

実装のフェーズは `squad-dispatch-pick implement "<小さな|大きな>"`、バグは `squad-dispatch-pick implement`、修正は `squad-dispatch-pick fix` で選ぶ。読み取りは 90 秒で打ち切るのでコマンドの時間切れは 120 秒以上にする。

終了コード 0 なら `役:` の印を、リーダーの指示の「このスクワッドの役」にある有効な役の一覧に対応させ、その完成したリンクで依頼する。`振り分け:` の行はそのまま依頼に添える。終了 2 なら両方に回せないので人間を呼ぶ。終了 1 は標準エラーの要約を添えて人間を呼ぶ。読めないときの代わりの決まりもスクリプトに任せる。

### Claude 系統だけのとき

`squad-usage-read` でその場の Claude の枠を読み、週または 5 時間の使用率が 80% 以上なら人間を呼ぶ。それ以外はこの系統の対応する実装・修正の役へ回す。読めなければこの系統に固定して選んだことと理由を書く。使用率の取得に失敗したとき、古い値を使わない。

### Codex 系統だけのとき

`squad-usage-read` でその場の Codex の枠を読み、週の使用率が 80% 以上か利用不可なら人間を呼ぶ。それ以外はこの系統の対応する実装・修正の役へ回す。読めなければこの系統に固定して選んだことと理由を書く。使用率の取得に失敗したとき、古い値を使わない。
