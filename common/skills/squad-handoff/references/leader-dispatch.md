# リーダーの手順: 実装・修正の振り分け

このファイルはリーダーの手順で、リーダーだけが読む。リーダーの指示の「場面と手順」から、実装や修正を頼むときに読む。前の実行で読んだ記憶で済ませず、その実行の中で読む。

役の有無と系統で分かれる手順は、場合分けで書く。どの場合かは、リーダーの指示の「このスクワッドの役」で決まる。有効な実装・修正の役の一覧も、そこにある。

## 回し先と使用率

新しくコードを書く仕事とバグは実装の役へ、レビューの指摘・コンフリクト・CI の失敗は修正の役へ回す。依頼ごとに `squad-usage-wait pick` で使用率を読み直して選び、30 分より古い値は使わない。上限に近くても、モデルを下げたり工程を飛ばしたりしない。空いている系統の役へ回すか、空きが戻る時刻まで待つ。

実装のフェーズを頼む前と、修正を頼む前に、`leader-principal.md` の「判断する時機」で印を確認する。最上位の役がないときは、この確認を飛ばす。

## 役の選び方

`squad-usage-wait pick <タスク> <implement | fix> [小さな | 大きな]` で選ぶ。実装のフェーズは `小さな` か `大きな` を添え、バグは添えない。修正は `fix` で、添えない。読み取りは 90 秒で打ち切るのでコマンドの時間切れは 120 秒以上にする。両系統の構成かは、スクリプトが名簿で決める。

| 終了コード | 意味 | すること |
| --- | --- | --- |
| 0 | 役を選んだ。`役:` と `振り分け:` の行を出す | `役:` の印を、リーダーの指示の「このスクワッドの役」にある有効な役の一覧に対応させ、その完成したリンクで依頼する。`振り分け:` の行はそのまま依頼に添える |
| 3 | 待つ。起こしを置き、`使用率の待ち:` の行を出す | 依頼を書かず、その行をタスクのコメントに写して終える。人間は呼ばない |
| 4 | 待ち始めから通算 24 時間を超える | `使用率の待ち:` の行を写して人間を呼び、待つか利用枠を足すかを決めてもらう。`in_review` にする |
| 1 | 使い方や読み取りの誤り | 標準エラーの要約を添えて人間を呼ぶ |

使用率を読めないときの代わりの決まりは、スクリプトに任せる。両系統があれば `squad-dispatch-pick` の代わりの決まりで、片系統ならその系統に固定して選ぶ。読めないことを理由に待たない。使用率の取得に失敗したとき、古い値を使わない。

## 使用率の待ちの起こしで起きたとき

指示が `使用率の待ちの起こしで起きました。` で始まる実行は、止めた工程をもう一度頼む。指示にある工程と、`decide` から待った回なら回のコメントの ID を読む。

1. 止めた工程が実装か修正なら、この手順で `squad-usage-wait pick` を流し直す。終了 0 なら依頼を書き、終了 3 なら、また待つ行を写して終える
2. 要件を決める役と設計の役の工程は、[leader-flow.md](leader-flow.md) の `pick` から頼み直す。最上位の役の工程は、[leader-principal.md](leader-principal.md) の `pick` から頼み直す
3. `decide` から待った回は、`squad-review-next decide <タスク> <回のコメント>` を流し直す。出力の `次の依頼:` の行を最後の返答にする

空きが戻っていれば、`pick` が役を選ぶので、そのまま工程が続く。まだ上限に近ければ、`pick` が起こしを置き直す。

## 24 時間を超えたあとに人間が待つと答えたとき

`pick` が終了 4 で終わると、リーダーは人間を呼んで `in_review` にする。人間が返事をしたら、答えを読み分ける。

- 待つと答えた: タスクのコメントに `使用率の待ちの延長: <工程>。決めた人: <名前>` の行を書き、`pick` を流し直す。行は、24 時間を超えた `使用率の待ち:` のコメントより後にだけ書く。上限に達する前に書いても数えられない
- 利用枠を足したと答えた: 延長の行は書かず、`pick` を流し直す。役が選べれば、工程が再開する
- 質問や、はっきりしない答え: 延長の行を書かず、もう一度人間に決めてもらう。質問だけでは待ち始めの時刻は新しくならない
