# multica-squad-kit

Multica のスクワッドを、プロジェクトごとに導入して更新するための原本。

対応する範囲は、macOS と Linux（WSL 2 を含む）、標準の bash・zsh、Claude Code と Codex の一方または両方、GitHub、日本語での利用です。WSL 1、WSL を使わない Windows、英語、GitHub 以外は対象外です。

自動テストで確かめる範囲は、macOS と Ubuntu 24.04 のセットアップ・再実行、関所の許可と拒否、見張り、シェル設定と時刻の読み取り、VM を作るスクリプトの引数と閉じ込めの設定です。CI でも両 OS に同じテストを流します。外部 CLI とサーバー、`limactl` と `wsl.exe` はスタブを使います。認証済みのデーモン・ランタイムの実行と、WSL 実機の動作は、VM を使わない普段のユーザーでは未確認です。WSL 2 は Linux との互換性と各ツールの公式対応に基づく対応です。

Mac の Lima の VM と WSL の専用のディストリは、VM を作るスクリプトで作り、中でセットアップを最後まで流すところまでを、新しいタグを付ける前に人が実機で確かめます。手順は [変更の進め方](CONTRIBUTING.md#版を出す前に-vm-で確かめる) にあり、結果は、そのタグを上げる PR に書きます。

公開リポジトリを clone してタグを取り出し、`bash setup.sh` を実行します。[導入と更新](manual.md)、[拡張の形式](EXTENSIONS.md)、[変更の進め方](CONTRIBUTING.md) を参照してください。

ZIP で導入済みの場合は、人がその関所・見張り・シェル設定と、対象プロジェクトの保存済み回答を消してから入れ直してください。回答の既定の保存先は `~/.multica-agent/template/answers/<workspace-id>/<project-key>.json` です。対象の確認と手順は [導入済みの配布物を入れ直す](manual.md#導入済みの配布物を入れ直す) を参照してください。

## 閉じ込めて動かす

普段のユーザーでセットアップすると、ホストに道具を入れ、ホームの下に設定とデーモンのファイルを置きます。エージェントは普段のユーザーで動くので、ホームの SSH の鍵や、普段の `gh` と Git の認証も読めます。これを避けたいときは、軽い VM の中でセットアップを流します。

Mac は Lima、Windows は WSL 2 の専用のディストリを、原本のスクリプトのコマンド 1 つで作ります。ホームの共有を切り、WSL では Windows のドライブと実行ファイルも切るので、中のエージェントはホストのファイルを読めません。中では Linux と同じセットアップを、変えずに流します。VM を消せば、ホストはセットアップの前に戻ります。

```bash
bash vm/lima.sh create
```

```powershell
powershell -ExecutionPolicy Bypass -File vm\wsl.ps1 create
```

使う Lima は 1.0.0 以上、WSL は 2.6.1 以上です。割くリソースの目安は、CPU 4、メモリ 8 GiB、ディスク 100 GiB です。Mac の Lima は、この値が既定で、`--cpus`、`--memory`、`--disk` で変えられます。WSL のメモリは、WSL 全体の `.wslconfig` で決まり、ディスクは使った分だけ伸びます。止めるときは `stop`、消すときは `delete` を同じスクリプトで流し、動いているタスクがあれば止まります。中でセットアップを流す方法と詳しい手順は、[閉じ込めて動かす](manual.md#閉じ込めて動かす) を参照してください。ネットワークは閉じ込めません。中のエージェントは、インターネットと、ホストで待ち受けるサービスに届きます。設計は [docs/vm.md](docs/vm.md) にあります。
