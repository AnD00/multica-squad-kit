# テストの作業

テストの正本は [CONTRIBUTING.md のテストを流す](../../CONTRIBUTING.md#テストを流す)と[テストを書く決まり](../../CONTRIBUTING.md#テストを書く決まり)です。検証コマンドと例外は `squadkit-verify` の対象リポジトリの節を参照します。

## 対象と置き場所

振る舞いを確認するシェルのテストは `tests/*-test.sh` に置き、`tests/run.sh` で実行します。補助のシェルや Python、PowerShell、CLI のスタブは `tests/` の既存の対象に合わせます。実行・分離・結果の集計の仕組みは [tests/run.sh の冒頭](../../tests/run.sh)を参照します。

## テストの書き方

変更する振る舞いと期待する結果を確認します。外部 CLI とサーバー、`limactl`、`wsl.exe` は既存のスタブを使い、実際のサービスへ登録や配信をしません。確認する範囲は [テストで確認する範囲](../../CONTRIBUTING.md#テストで確認する範囲)に従います。

一時ファイルの置き場所、`HOME` と `TMPDIR`、Git の名前とメール、プロセスの扱いは[テストを書く決まり](../../CONTRIBUTING.md#テストを書く決まり)を守ります。並列で流れる前提で、自分のテストの領域だけを使います。

## 環境を使うとき

外部サービスや DB を使う専用環境は対象外です。テストで作った領域の片付けは `squadkit-verify` の片付けの節に従い、ほかの実行のファイルを消しません。VM の実機確認は自動テストの成功と分け、人間がリリース前に行います。
