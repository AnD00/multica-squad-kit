# コードの作業

このルールは、セットアップの処理と配布する原本に使います。[リポジトリの指示](../../AGENTS.md)と、対象の設計を先に読みます。

## 設計と依存

動作の契約は [manual.md](../../manual.md)、拡張の形式は [EXTENSIONS.md](../../EXTENSIONS.md)、個別の設計は [docs/](../../docs/) を参照します。`setup.sh` は `lib/` を読み、`common/` と `skeleton/` を展開して配置・登録します。利用者の配置先だけを直して原本と食い違わせません。

役・スクワッド・オートパイロットの記法と展開順は [common/agents/FORMAT](../../common/agents/FORMAT) に従います。導入先ごとに違う値を共通の原本へ固定せず、既存の差し込みと条件の仕組みを使います。

## 実装の規則

シェルは macOS 標準の bash 3.2 と zsh、Ubuntu 24.04 での動作を保ちます。Python は 3.11 以上を前提とします。VM は Lima と WSL の役割を分け、ゲストとホストの境界は [VM の設計](../../docs/vm.md)に従います。

セットアップの表示・色・印と、色を付けない出力の扱いは [画面に出す文](../../CONTRIBUTING.md#画面に出す文)に従います。色の制御文字を直接書かず、`lib/ui.sh` を使います。

## 変更時の確認

役や条件の変更では、有効・無効の役と利用するランタイムの組み合わせ、差し込みの不足、再実行時の既存設定への影響を確認します。外部 CLI の応答を変えるときは、対応するテストのスタブも実際の契約と合わせます。

検証は `squadkit-verify` の対象リポジトリの節に従います。VM を変えたときは、スタブの自動テストと人間による実機確認の範囲を分けて報告します。MANIFEST の更新と公開の扱いは [リポジトリの指示](../../AGENTS.md#作業の進め方と守ること)に従います。
